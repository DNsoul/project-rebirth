# Rebirth

Личный VPN для небольшого круга людей на AmneziaWG 3.1. Приложение для Windows и
Android с одной кнопкой. Серверы заменяют себя сами, а приложения сами находят
новый и переходят на него. Это не сервис и не продукт: проект делается под одного
оператора и тех, кому он даёт приложение.

## Как это работает

- **Серверы меняются сами.** Каждый сервер (сейчас Vultr) по истечении срока (и, если
  это включено, при блокировке) сам поднимает себе замену, публикует новый конфиг, а
  потом удаляет себя. Оператору для этого ничего делать не нужно.
- **Конфиг лежит в двух равных местах**: в секретном gist на GitHub и в пакете на
  GitLab. Он зашифрован и подписан, подпись проверяют приложения, поэтому подменить
  сервер, не имея ключей оператора, нельзя. Главного места нет: запись идёт в оба,
  отставшее место догоняется само, а приложение читает оба и берёт более свежее.
  Устройство регистрируется на сервере само, при первом подключении.
- **Разделение трафика на сервере.** Сайты, чьи адреса в российских сетях, идут
  напрямую, остальное через туннель (`rules/` — исключения в обе стороны).
- **Приложения сами узнают о новой версии**: оператор объявляет её подписанным
  анонсом, приложение предлагает обновиться и ставит файл, только если его размер и
  SHA-256 совпали с подписанными.

Форматы и ключи: [`spec/format.md`](spec/format.md). Устройство приложений:
[`app/README.md`](app/README.md).

## Установка

Установщики лежат в разделе
[Releases](https://github.com/DNsoul/project-rebirth/releases) этого репозитория.

- **Windows 10 и новее.** Запустить `Rebirth-Setup-<версия>.exe`. Windows спросит права
  администратора, они нужны приложению для управления туннелем. Установщик может
  включить запуск вместе с Windows: приложение тогда стартует свёрнутым в трей и
  подключается само. Ничего другого ставить не нужно: туннель (служба на библиотеке
  AmneziaWG и адаптер Wintun) приложение возит с собой. Установщик не подписан
  сертификатом, поэтому SmartScreen скажет «неизвестный издатель».
- **Android 7 и новее, любое устройство** (arm64, 32-битный ARM, x86_64: один
  универсальный APK, около 55 МБ). Установить `Rebirth-<версия>.apk`. Система попросит
  разрешить установку из этого источника и при первом подключении разрешение на VPN.

Дальше приложение предлагает обновления само: вдоль верхнего края окна появляется
строка «Версия …» с кнопкой «Обновить».

## О доступе

Установщики и APK содержат данные для доступа: адрес секретного gist и ключи для
расшифровки конфига. Кто получил сборку, тот может читать конфиг. Подключиться может
только устройство, которое пустил владелец: с включённым одобрением каждое новое
устройство сначала ждёт, приложение показывает четыре цифры, а владельцу в Telegram
приходит заявка с моделью устройства и теми же цифрами. Владелец одобряет или
отказывает, может позже отозвать доступ или выдать его снова. Переустановка приложения
меняет ключ устройства, и заявка приходит снова.

## Тому, кто ведёт серверы

Нужны Go 1.26+, ключ API Vultr и токен GitHub с правом работать с gist. Они кладутся в
`secrets.env` в корне проекта (в репозиторий не попадает):

```
VULTR_API_KEY=...
GITHUB_TOKEN=...
GITLAB_TOKEN=...   # необязательно: второе место на GitLab (установщики и файлы конфигурации)
TELEGRAM_BOT_TOKEN=...   # необязательно: бот для управления (у @BotFather: /newbot)
```

```powershell
cd go
go build -o ..\dist\awgctl.exe .\cmd\awgctl
cd ..
dist\awgctl.exe init                 # ключи и секретный gist, один раз
dist\awgctl.exe up                   # сервер, который дальше заменяет себя сам
dist\awgctl.exe trust -o app\assets\bootstrap.json   # доступ, с которым собираются приложения
dist\awgctl.exe status               # ключи, gist, серверы
dist\awgctl.exe command move         # приказать серверу переехать сейчас
dist\awgctl.exe release publish ...  # объявить новую версию приложений
dist\awgctl.exe mirror set gitlab -project владелец/имя   # второе место: установщики и конфиг
dist\awgctl.exe mirror token        # токен, которым серверы пишут на GitLab (один раз)
dist\awgctl.exe mirror sync         # сверить оба места и догнать отставшее
dist\awgctl.exe watch                # журнал доступности сервера: терял ли он связь с Россией
dist\awgctl.exe update -manager      # обновить только менеджера на сервере, без разрыва подключений
```

**Журнал доступности.** Менеджер на сервере раз в две минуты спрашивает сам себя, получает
ли он ещё ответы от российских сайтов (TCP 443 к двенадцати сайтам и UDP DNS к Яндексу, с
зарубежным контролем), и пишет одну строку в `/var/lib/awgmgr/watch.jsonl` вместе с тем,
что делают его клиенты и что показала проверка с российских точек. Журнал только пишется
и ни на что не влияет: переездов он не вызывает. Нужен затем, чтобы после настоящей
блокировки сравнить, когда её заметил сервер, когда внешняя проверка и когда пропали
клиенты. `awgctl watch` показывает этот разбор. Журнал передаётся преемнику при переезде
и поэтому переживает заблокированный сервер; коротко о нём сказано и в `awgctl events`,
а это приходит через GitHub и GitLab, даже если на сам сервер не попасть.

**Бот в Telegram.** Его ведёт менеджер того сервера, которым сейчас пользуются
приложения; при переезде бот переходит на новый сервер вместе со списком устройств,
заявками и отказами. Отвечает только владельцам, всем остальным — ни слова. В боте:
состояние сервера, устройства (модель, код, в сети ли), заявки и отказы, переезд сейчас
или в выбранный регион, перезапуск туннеля, автопереезды вкл/выкл, проверка доступности
из России. Адресов бот не присылает: ни сервера, ни пользователей.

```powershell
dist\awgctl.exe telegram link         # написать боту /start: аккаунт станет владельцем
dist\awgctl.exe update                # бот на работающем сервере, одобрение пока выключено
dist\awgctl.exe update -approval on   # новые устройства ждут одобрения
dist\awgctl.exe telegram show         # бот, владельцы, одобрение
```

Устройства, которые уже были до включения одобрения, остаются одобренными. Если бот
перестал работать, одобренные устройства продолжают работать, а новые ждут; аварийный
выход — `awgctl update -approval off`. Аккаунт Telegram владельца становится ключом от
VPN: включите в нём облачный пароль.

Остальные команды: `awgctl` без аргументов. Состояние, включая все ключи, лежит в
`state/`. Эта папка должна быть в резервной копии вне компьютера, а в репозиторий
она не попадает.

## Сборка из исходников

Нужны Flutter, Go и для Android NDK и Android Studio. Подробности и подводные камни
в [`app/README.md`](app/README.md).

```powershell
.\scripts\build-windows.ps1     # dist\rebirth-windows\Rebirth.exe
.\scripts\build-installer.ps1   # установщик Windows (нужен Inno Setup 6.3+)
.\scripts\build-android-lib.ps1 # libawg.so, библиотека туннеля для Android
.\scripts\make-android-key.ps1  # один раз: ключ подписи APK
.\scripts\build-android.ps1     # подписанный APK
.\scripts\build-release.ps1     # оба файла сразу и команда для объявления версии
```

Проверка:

```powershell
cd go;  go vet ./...; go test ./...
cd ..\app; flutter analyze; flutter test
cd packages\awg_proto; dart test
```

Две реализации форматов (Go и Dart) держатся на общих контрольных векторах в `spec/`.

## Что где

```
go/cmd/        awgctl (оператор), awgnode (узел на сервере), awgmgr (менеджер, сам
               заменяет сервер), awglib (библиотека туннеля для Android), awgprobe,
               awgwatch, awgsoak (проверки)
go/internal/   протокол, жизненный цикл сервера, разделение трафика, клиенты API
app/           приложение на Flutter: Windows и Android
spec/          форматы документов и контрольные векторы
rules/         сайты, которые всегда идут напрямую или всегда через туннель
installer/     установщик Windows (Inno Setup)
scripts/       сборка, иконки, установщик, подпись APK, выпуск
branding/      значок приложения
```
