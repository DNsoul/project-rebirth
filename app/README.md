# Rebirth

Одна кнопка. Приложение читает из секретного gist, где сейчас сервер, регистрирует
это устройство на нём само, поднимает туннель и переходит на новый сервер, когда
сервер меняется.

```
app/
  packages/awg_proto/   форматы из spec/format.md на Dart; держатся на spec/*vectors.json
  lib/core/             логика подключения: одна и та же для Windows и Android
  lib/platform/windows/ туннель через установленный AmneziaWG, правила имён, защита от перезагрузки
  lib/platform/android/ туннель в самом приложении (libawg.so) на VPN-интерфейсе системы
  lib/app_windows.dart, lib/app_android.dart   то, чем системы различаются; lib/app.dart и lib/ui общие
  android/              Kotlin: MainActivity (разрешение, мост) и AwgVpnService (интерфейс)
  lib/ui/               экран
  test/                 тесты логики (с поддельными сервером и туннелем), ввода-вывода и экрана
```

## Как собрать

```powershell
.\scripts\build-windows.ps1            # dist\rebirth-windows\Rebirth.exe, просит права администратора
.\scripts\build-windows.ps1 -NoElevation   # для разработки: открывается из обычной консоли, подключиться не может
.\scripts\build-android-lib.ps1        # libawg.so (arm64-v8a и x86_64) в app\android\...\jniLibs
cd app; flutter build apk --debug --target-platform android-arm64
```

## Android: как это устроено

- Туннель не зависит от других приложений: `go/cmd/awglib` собирается тем же
  `amneziawg-go`, что и серверы, в `libawg.so` (нужен NDK из Android Studio).
  Dart вызывает её напрямую через FFI (`lib/platform/android/awg_native.dart`).
- Система даёт приложению VPN-интерфейс (`VpnService`), Kotlin отдаёт его
  файловый дескриптор библиотеке, и дальше пакеты ходят в ней. Адреса, сети и
  сервер имён интерфейс берёт из того же файла настроек (`conf_plan.dart`), поэтому
  отдельного правила для имён, как NRPT в Windows, не нужно.
- Android держит один VPN-интерфейс на приложение: новый заменяет старый, и
  переход на другой сервер идёт с самым коротким разрывом.
- Библиотека открывает TUN без netlink-монитора (`CreateUnmonitoredTUNFromFD`):
  монитор Android приложениям не разрешает.
- Первый запуск спрашивает разрешение на VPN. Если пользователь отказал или
  система отобрала VPN (другое VPN-приложение), экран возвращается в «отключено».

Нужен `dist\awgctl.exe`: из него берутся данные для доступа
(`awgctl trust -o app\assets\bootstrap.json`). Этот файл и есть доступ, в репозиторий
он не попадает. Кто получил сборку, тот может читать конфиг.

## Что нужно на машине

- AmneziaWG для Windows (`C:\Program Files\AmneziaWG`). Приложение просит его
  службу ставить и убирать туннели, сам протокол оно не реализует.
- Права администратора. Windows спросит один раз при запуске.
- Лучше выключить другие VPN на время проверки: правило имён одно на всю систему.

## Что приложение делает с системой

- ставит службы `AmneziaWGTunnel$awgr-a`, `awgr-b` (рабочие туннели, по очереди) и
  `awgr-enroll` (на время регистрации); трогает только имена с префиксом `awgr-`;
- службы запускаются вручную, а не при старте системы;
- добавляет правило разрешения имён «все имена спрашивать у 198.18.0.1» с пометкой
  `awg-rotator`; убирает только свои;
- ставит задачу «awg-rotator cleanup», которая при старте системы убирает это правило:
  иначе после перезагрузки с включённым VPN имена бы уходили в никуда;
- пишет файлы в `%LOCALAPPDATA%\awg-rotator` (состояние, журнал `app.log`) и
  `%ProgramData%\awg-rotator` (конфиги туннелей, закрытые для всех, кроме
  администраторов).

## Экран

Плоский минимализм: сплошные цвета, без градиентов, размытия, теней, карточек и рамок.
На экране три вещи, и больше ничего, никаких надписей:

- **По центру, точно по центру окна, кнопка** с птицей и свет костра вокруг неё
  (`lib/ui/stage.dart`). Состояние выражено видом кнопки и светом, словами нет:
  - выключено: тёмная кнопка, серая птица, света нет и ничего не движется;
  - подключение: жёлтая птица, по кольцу бежит искорка, свет разгорается быстро и
    неровно, поднимаются искры;
  - подключено: оранжевая птица, свет дышит медленно (период 3,4 с), несколько искр;
  - переход на другой сервер: то же, но свет вспыхивает чаще, искр больше, по кольцу
    бежит искорка;
  - сервер молчит: тусклая птица, кольцо пунктиром, свет еле теплится и вздрагивает;
  - отключение: птица гаснет, свет затухает, искорка бежит назад;
  - ошибка: красная птица, красный свет бьётся двумя ударами и паузой, как сердце;
    кольцо разомкнуто со стрелкой «ещё раз». Нажатие повторяет попытку.
  Свет это три полупрозрачных круга один в другом, каждый чуть позже предыдущего
  «дышит», и плоские точки-искры. Часы анимации идут, только пока что-то движется;
  при «убрать анимацию» в системе свет стоит неподвижно.
- **Сверху, вплотную к краю, одна строка**, только когда вышла новая версия: «Версия
  1.2.0» и «Обновить». Вся строка нажимается. Закрыть её нельзя: она пропадает, когда
  версия поставлена. Скачивание показывает процент и тонкая линия.
- **Снизу, вплотную к краю, полоса с ошибкой**, только когда что-то не так: первое
  предложение жирным (что случилось), остальное тусклым (что делать). Текст можно
  выделить и скопировать. Тут же ошибки обновления. Предупреждения (например, «новый
  сервер не отвечает, остаёмся на прежнем») того же вида, но жёлтые.

Полосы лежат поверх краёв и ничего не сдвигают, поэтому прокрутки нет, и кнопка не
двигается, когда они появляются. Размер кнопки зависит от окна: не больше 60% ширины
и 40% высоты, от 110 до 250 пикселей, так что места сверху и снизу хватает всегда.
Сообщения об ошибках пишутся по образцу «Что случилось. Что делать.» и разбираются по
первому предложению (`lib/ui/error_panel.dart`).

Картинки всех состояний рисует
`BRAND_DIR=... flutter test test/screen_preview_test.dart`.

## Окно и значок в трее

- Окно узкое, как у телефона, одного размера (340×560, внутри 324×521), без кнопок
  «свернуть» и «развернуть». Кнопка «закрыть» не завершает приложение, а прячет окно:
  оно продолжает работать и переключаться на новые серверы.
- Значок в области уведомлений показывает состояние: серый — отключено, зелёный —
  подключено, жёлтый — идёт работа или сервер молчит, красный — ошибка. В подсказке
  название состояния и сервер (при ошибке — причина).
- Щелчок по значку открывает окно. Правая кнопка: строка состояния, «Подключить /
  Отключить / Повторить», «Открыть окно» и «Выход».
- Завершить приложение можно только через «Выход» в меню значка: он отключает VPN и
  возвращает системе её имена. Значки рисует `scripts\make-icons.ps1`.
- Значок, его меню и «закрыть = спрятать» сделаны в родном коде окна
  (`windows\runner\tray_icon.cpp`, `flutter_window.cpp`), а не плагинами. Закрытие
  прячет окно сразу, не дожидаясь Dart; значок обновляется в отдельном потоке.
  Обращение к области уведомлений ждёт Explorer, а он тормозит секундами именно тогда,
  когда появляется или исчезает сетевой адаптер, то есть при подключении и
  отключении; в одном потоке с окном это замораживало нажатия и закрытие.
- Запустить программу второй раз нельзя: второй запуск просто показывает окно
  первого. Иначе он при старте снёс бы туннели работающего экземпляра.
- Ключ `--quit-after=N` для проверки: приложение само выходит тем же путём, что и
  «Выход», через N секунд.

## Отзывчивость

- Экран отвечает на нажатие сразу: состояние меняется раньше, чем начинается что-то
  медленное. Шаги («Читаю настройки…», «Поднимаю туннель…», «Жду ответа сервера…»,
  «Убираю за собой…») остаются в состоянии и в журнале, на экране их нет: о том, что
  идёт работа, говорит бегущая по кольцу искорка.
- Любая операция отменяется. Пока идёт подключение, нажатие на кнопку отменяет его,
  «Отключить» прерывает то, что выполняется, а не ждёт своей очереди (`CancelToken`
  в `lib/core/cancel.dart`).
- Туннели и правило имён снимаются одновременно; правило имён трогается, только если
  оно могло быть поставлено (PowerShell стоит около секунды за вызов). Состояние
  служб читается через `sc.exe` и `reg.exe` (десятки миллисекунд).
- Если что-то всё же тормозит, это видно в журналах:
  `%LOCALAPPDATA%\awg-rotator\app.log` — время каждого шага (`connect: settings 412
  ms`) и строки `ui: the program was stuck for N ms` (окно не отвечало N мс; пишет
  `StallWatchdog`); `native.log` — вызовы значка в трее, которые заняли больше 150 мс
  или не удались.

## Обновления

Приложение само узнаёт, что вышла новая версия, и предлагает её поставить.

- Оператор объявляет версию подписанным анонсом (`spec/format.md`, раздел 4.6,
  файл `u` в gist): номер версии, номер сборки, адреса установщиков, их размер и
  SHA-256, что нового. Подписывает главный ключ; адрес — только место, откуда
  качать, а что файл тот самый, решает подписанный хеш.
  ```powershell
  dist\awgctl.exe release publish `
      -windows dist\Rebirth-Setup-1.1.0.exe -android dist\Rebirth-1.1.0.apk `
      -base-url https://github.com/DNsoul/project-rebirth/releases/download/v1.1.0/ `
      -notes "Что нового" -dry-run      # без -dry-run публикует
  dist\awgctl.exe release show         # что опубликовано сейчас
  ```
  Версия и номер сборки берутся из `app/pubspec.yaml`: установщики собраны из него,
  и их внутренний номер должен совпадать с объявленным. Сборку ниже уже
  опубликованной команда не публикует: приложения, видевшие новую, запомнили её
  номер и отбросили бы эту. `-min-build N` делает обновление обязательным для сборок ниже N.
- Приложение читает анонс вместе с конфигом: при запуске, затем раз в 6 часов, а
  подключённое — каждые 3 минуты. Принятый анонс хранится в `state.json` и при
  чтении проверяется заново.
- Вдоль верхнего края окна появляется строка «Версия …» с «Обновить»; нажимается вся
  строка, закрыть её нельзя (см. «Экран»). Файл скачивается
  только по https, не больше объявленного размера; ставится, лишь если размер и
  SHA-256 совпали с подписанными (`lib/core/updater.dart`, `http_downloader.dart`).
- Windows: запускается скачанный установщик (`/SILENT /SUPPRESSMSGBOXES
  /NORESTART`), приложение отключает туннель и выходит, чтобы установщик мог заменить
  файлы; приложение уже работает с правами администратора, и установщик их наследует.
  Установщик должен само приложение запустить снова.
- Android: файл показывается системному установщику через `FileProvider`. Первый
  раз система просит разрешить этому приложению установку неизвестных приложений:
  приложение открывает нужную страницу настроек и просит нажать «Повторить» после
  включения. Обновление ставится поверх, только если подписано тем же ключом, что и
  установленное.
- Номер сборки в коде (`lib/core/version.dart`) держится тестом на `pubspec.yaml`.

## Установщик для Windows

`.\scripts\build-installer.ps1` собирает приложение и упаковывает его в
`dist\installers\Rebirth-Setup-<версия>.exe` (версия из `app\pubspec.yaml`, скрипт
`installer\rebirth.iss`). Нужен Inno Setup 6.3 или новее
(https://jrsoftware.org/isdl.php; скрипт ищет `ISCC.exe` сам). В конце он печатает размер,
SHA-256 и заготовку команды `awgctl release publish`.

- Ставит в Program Files, добавляет ярлык в меню «Пуск» (и по желанию на рабочий стол)
  и деинсталлятор. Права администратора просит один раз: приложению они нужны само.
- Галочка «Запускать вместе с Windows» создаёт задачу «Rebirth» (`installer\autostart.ps1`):
  при входе любого пользователя, через 15 секунд, с высшими правами пользователя,
  без запроса при каждом входе, и на батарее тоже. Задача запускает
  `Rebirth.exe --autostart`: окно остаётся скрытым, приложение сидит в трее и
  подключается само, а если сеть ещё не поднялась, повторяет попытки около полутора
  минут (`lib/core/logon_connect.dart`). Если приложение уже запущено, второй запуск
  ничего не показывает. Выбор галочки запоминается: тихое обновление его не меняет.
- `Rebirth.exe --quit` просит уже запущенную копию выйти тем же путём, что и пункт «Выход»,
  и ждёт, пока она не выйдет (до 30 секунд). Это делают установщик и деинсталлятор до
  замены файлов: иначе приложение пришлось бы убивать, а убитое, оно оставляет
  туннель и правило имён. Работает без движка Flutter, это пара десятков строк в
  `windows\runner\main.cpp`.
- Тихий запуск (`/SILENT`, так обновляется само приложение) в конце запускает
  приложение снова. Обычный показывает «Запустить Rebirth».
- AmneziaWG для Windows установщик не содержит: он проверяет `Program Files\AmneziaWG`
  и, если его нет, в конце пишет об этом и предлагает открыть страницу загрузки.
- Установщик не подписан сертификатом, поэтому SmartScreen при первом запуске скачанного
  из браузера файла скажет «неизвестный издатель». Обновление изнутри приложения этого
  предупреждения не вызывает.
- Удаление убирает файлы, задачи «Rebirth» и «awg-rotator cleanup» и
  `%ProgramData%\awg-rotator`. Файлы пользователя (`state.json`, журнал в
  `%LOCALAPPDATA%\awg-rotator`) остаются: при переустановке устройство остаётся
  зарегистрированным.

Проверено на этой машине вариантом установщика без прав администратора (другой код
приложения, другие имена задач, папка во временной): установка, обновление поверх
работающего приложения (оно корректно вышло и запустилось заново) и удаление. Не
проверялось без администратора: создание задачи для группы «Пользователи» и её
срабатывание при входе, окна обычной установки.

## Подписанный APK для Android

`.\scripts\build-android.ps1` собирает `dist\installers\Rebirth-<версия>.apk` (только
arm64: библиотеки туннеля для 32-битных ARM нет) и проверяет подпись.

Android ставит обновление поверх установленного приложения, только если оно подписано
тем же ключом, поэтому все APK, которые кто-то получает, подписаны одним постоянным
ключом. Его один раз делает `.\scripts\make-android-key.ps1`: хранилище и пароли лежат
в `state\android-signing` (вне репозитория, как и остальные ключи), пароли случайные,
на экран не выводятся. **Папка `state\` должна быть в резервной копии вне этого
компьютера.** Потеряв ключ, придётся просить всех удалить приложение и поставить
заново. Скрипт сборки отказывается работать без этого ключа и сверяет сертификат
в готовом APK с сертификатом ключа (Gradle: `app/android/app/build.gradle.kts`;
для отладочного запуска без ключа берётся отладочная подпись, но только если не задано
`REBIRTH_REQUIRE_RELEASE_KEY`, которое скрипт сборки ставит сам).

## Выпуск новой версии

1. Поднять версию в `app/pubspec.yaml` (`version: 1.2.0+12`) и в
   `app/lib/core/version.dart`, прогнать тесты. Номер сборки (после `+`) должен расти с
   каждым выпуском: по нему приложения решают, что вышла новая версия.
2. `.\scripts\build-release.ps1` собирает установщик Windows и APK в `dist\installers`
   и печатает команду для шага 4.
3. Создать релиз на GitHub с тегом `v<версия>` и загрузить в него оба файла.
4. Объявить версию: `dist\awgctl.exe release publish ... -dry-run`, затем без
   `-dry-run`. После этого приложения у всех увидят обновление.

## Чего пока нет

- загрузки релиза в GitHub одной командой (шаг 3 делается руками);
- проверки обновления на живом анонсе: ни один анонс в настоящий gist пока не
  публиковался.

## Что уже ломалось на настоящей Windows, и почему это важно знать

- Вывод программ на русской Windows не UTF-8: строгое декодирование убивало
  приложение при старте.
- Сразу после запуска службы туннеля маршрута ещё нет, и первая отправка получает
  ошибку 1232 («узел недоступен»). Сокет, сообщивший её, больше нельзя использовать.
- Вызов `setSkipTaskbar` из `window_manager` приводил к нарушению доступа внутри
  плагина, а `destroy()` к падению движка при выходе. Плагины `window_manager` и
  `tray_manager` убраны совсем: у скрытого окна и так нет кнопки на панели задач, а
  выход делается через `exit(0)` после того, как всё убрано.
- Flutter на Windows гоняет интерфейс и события окна в одном потоке, поэтому любой
  блокирующий вызов в нём (в том числе `Shell_NotifyIcon`) замораживает нажатия,
  отрисовку и закрытие. `Process.run` и криптография его не блокируют (замерено,
  `tool\bench_blocking.dart`), а PowerShell обходится в 0,8–1,2 с на вызов.
